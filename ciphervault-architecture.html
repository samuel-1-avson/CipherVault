01 — System Architecture & Trust Boundaries

Plaintext never leaves the workstation. Operators hold opaque ciphertext addressed by content digests (CIDs). Settlement is the sovereign CipherChain ledger — no EVM, no gas.

02 — End-to-End System Workflow (7 stages)

Happy path from vault bootstrap to disaster recovery. Every stage is a real CLI command; operators never see plaintext at any step.

STAGE 1 — INIT
Bootstrap trust
init → R(32 B) → kit print → DPAPI persist → track discovered .env
STAGE 2 — TRACK
Version secrets
diff masked by default; --reveal only for explicit audit
STAGE 3 — PUSH
Encrypt + replicate
chunk → FVK/nonce → seal → PoS-or-PUT → SnapshotRecord → quorum
STAGE 4 — ANCHOR
Settle state
anchor → salt+commit → PoA propose/commit → gossip publish
STAGE 5 — HEAL
Stay durable
daemon probes, audits closure, re-replicates to heal 3/3
STAGE 6 — USE
Consume safely
run -- cmd injects env in RAM; pull syncs second machine
STAGE 7 — RECOVER
Survive loss
kit/shares → L → envelope → head → chunks → atomic bit-for-bit restore

Trust boundaries

  • • Trusted: workstation RAM, OS keyring (DPAPI), YubiKey PIV
  • • Untrusted: operators see CIDs + ciphertext only
  • • Public: vault/epoch headers, sizes, access patterns
  • • Rule: node count ≠ failure domains — verify ops

Crypto & data plane

  • • Seal: XChaCha20-Poly1305, AAD = CID
  • • Keys: Blake2b-KDF tree from R; deterministic FVK/nonce
  • • Chunks: v2 FastCDC dedup; v1 whole-file compat
  • • Sign: Ed25519 device cert / Slot 9C touch

Operations & recovery

  • • API: Axum :8201–8203, P2P Kademlia/Gossipsub
  • • Health: 15 s heartbeats, PoS audits, self-repair
  • • Ledger: CipherChain PoA, 2N/3+1, median time
  • • DR: paper kit or Shamir M-of-N, atomic restore
